## 1. Claude / Anthropic 对 harness 的核心观点

### 1.1 Context engineering

- Context = 有限注意力预算，不是越大越好（**context rot**）。
- 相对 prompt engineering：要管的是**整轮推理时进入窗口的全部 token**（system、tools、history、MCP…），且**每轮都要重新策展**。
- 原则：用**尽量少、尽量高信噪**的 token 最大化期望行为。

### 1.2 长程任务三杠杆

1. **Compaction** — 摘要旧历史，开新窗口继续  
2. **Structured note-taking** — 重要状态落到文件（TODO/NOTES），compact 后再读回  
3. **Sub-agents** — 探索用干净窗口，只带回 condensed 结果（课程可后置）

Claude Code compact 实践要点：

- 用模型摘要：保留架构决策、未解决问题、实现细节；丢掉冗余 tool 输出。
- 继续时：**压缩摘要 + 最近访问过的若干文件**（常说最近 5 个）。
- 最轻量的压缩：清掉旧 tool result（平台已有 `clear_tool_uses`）。

### 1.3 Claude Code 五层渐进压缩（lazy degradation）

每轮 model call 前依次执行（越后面越贵、越狠）：

| # | 层 | 作用 |
|---|----|------|
| 1 | Budget reduction | 单条 tool 输出限长（Nan spill ≈ 此层） |
| 2 | Snip | 轻量裁掉更旧历史 |
| 3 | Microcompact | 清旧 tool result；可走 cache_edits，少动结构 |
| 4 | Context collapse | **读时投影**；全量 transcript 仍在，模型看到折叠版 |
| 5 | Auto-compact | 最后才 LLM 全文摘要（≈ `/compact`） |

其它要点：

- **绝不拆** `tool_use` / `tool_result`；同 `message.id` 的 thinking 也不拆。
- Full compact 后结构大致：`boundary + summary + messagesToKeep`，再 **re-announce** plans/skills（附件被丢掉，状态还在）。
- Compact API 调用尽量**复用主会话 prompt cache 前缀**（实验：不复用 ≈ 98% cache miss）。
- Transcript 多为 append-only：compact 追加 boundary/summary，不改历史行。

### 1.4 上下文组装（Claude）

大致顺序：system → env（git 等，memoize）→ CLAUDE.md 层级（user context）→ 路径级 rules（懒加载）→ auto memory → tool/skill 元数据 → 对话历史 → tool results → compact 摘要。

扩展成本分层：skills 只广告 name+description；正文经 Skill 工具按需加载（progressive disclosure）。

## 2. `/compact`：摘要且不拆 tool 对

### 2.1 正确流程（对齐 Pi + Claude）

```text
1. 从新往旧累加 token/chars，直到 keepRecent（建议 ~20k）
2. cut 只能落在合法 cut point：
   - user 消息，或
   - 带 tool_calls 的 assistant（其后整组 tool results 一起保留）
   - 绝不单独切在 tool 消息上
3. cut 之前：另起 LLM 调用做结构化摘要（可带 customInstructions，如 /compact focus on auth）
4. 会话替换为：
   [system / baseline]
   [user: <COMPACT_SUMMARY>…</COMPACT_SUMMARY>]
   [kept recent blocks 原样]
5. （可选）附上最近读写路径，提示可再 read_file
```

### 2.2 摘要应保留 / 应丢弃

**保留：** 用户目标、已做决策、未完成项、关键路径与命令、失败尝试与原因。  
**丢弃：** 大段 tool dump、重复读文件原文、中间探索噪音。

### 2.3 自动触发

- `transformContext`：超 soft threshold → 先 microcompact；仍超 → auto-compact。
- API `context_length` / prompt_too_long → reactive compact 一次再重试。

### 2.4 Nan 现状改造点

- `AgentRuntime.compact()` 改为 LLM compact，不再只调用 `compactMessagesInPlace`。
- `groupMessageBlocks` / cut-point 逻辑抽成可单测模块。
- Session 可记 `compactBoundary` / 最近文件列表。

## 3. Context Epochs / cache 友好重组

### 3.1 OpenCode 术语（推荐采用）

| 术语 | 含义 |
|------|------|
| **Baseline System Context** | Epoch 开头冻结的 system 前缀（provider cache 友好） |
| **Context Epoch** | baseline 字节不变的区间；compact / 换目录 / 不兼容切换 → 新 epoch |
| **Mid-Conversation System Message** | 中途变更写成 chronological 指令，**不改写**已发 baseline |
| **Context Source** | 独立可观察的一块上下文（git、date、instructions、skills…） |
| **Context Snapshot** | 上次已 admit 的各 source 取值，用于 diff |
| **Safe Provider-Turn Boundary** | 下一轮 API 前、tool 已结算；只在此承认上下文变更 |

### 3.2 为什么对 cache 重要

Prompt cache（及多数网关隐式缓存）按**前缀字节**命中。每轮改 system 里的 git/date/skills → 整段 cache 废。

理想请求形状：

```text
system = Baseline（整 epoch 不变）
messages = [
  …对话…
  （可选）Mid: "Git status updated: …"   // 仅变化时追加
  user / assistant / tool…
]
```

Compact 完成后：**新 epoch** = 把当前完整 System Context 重新渲染进新 baseline；旧 mid-system 从 **projected** history 移除（审计日志可留）。

Codex 社区「generational / within-epoch append-only」与此同构。

对 Nan（OpenAI-compatible）：即使没有 Anthropic `cache_control`，稳定前缀仍利于网关缓存与行为可预期。

### 3.3 注意

- 变更采样要 **lazy**：在 Safe Boundary 比较 Snapshot，不要 watcher 异步塞消息。
- Anthropic 拒绝会拆开本地 tool call / result 的 chronological system 插入 → mid 消息只能插在 tool 对之外的安全位置。

## 4. 动态系统上下文（技能列表、中途刷新）

### 4.1 模式

- **广告轻、正文重**：context 里只放 skill **name + description**。
- 正文经 `skill` 工具（或 `read_file`）按需加载。
- 技能列表本身是一个 ContextSource；agent/权限变化 → Mid message，或 compact 后进新 baseline。

### 4.2 建议 Nan ContextSource（课程可落地）

| key | 刷新策略 | 内容 |
|-----|----------|------|
| `role+tools` | epoch 开始 / mode 切换 | agent vs plan |
| `env` | Periodic 或 OnChange | workspace、OS、date |
| `git` | OnChange（status 哈希） | branch dirty |
| `instructions` | OnChange（mtime） | AGENTS.md / CLAUDE.md |
| `skills`（可选薄实现） | OnChange | 目录扫描 name+desc |
| `mode` | 切换时 mid-message | `/plan` ↔ `/agent` |

采样时机：仅在 `callLlm` 之前（Safe Provider-Turn Boundary）。

### 4.3 与 `refreshSystemPrompt` 的关系

当前 `setMode` → 整段替换 session 唯一 system，会破坏 epoch/cache。应改为：

- 普通变更 → append Mid-Conversation System Message；或  
- 不兼容变更 / compact 后 → `replace()` 开新 epoch。

## 5. 建议 Nan 落地架构

```text
src/agent/context/
  blocks.ts          # groupMessageBlocks（从现 context.ts 抽出）
  microcompact.ts    # 旧 tool result → stub（保留 tool_call_id）
  compact.ts         # LLM 摘要 + cut point + 写回 session
  sources.ts         # ContextSource + git/date/instructions/mode
  assemble.ts        # epoch baseline + mid updates + transformContext 管线
```

每轮 `callLlm` 前：

```text
refresh sources (lazy)
→ admit mid-system if changed（tool 已结算之后）
→ microcompact（可选）
→ prune / auto-compact if over budget
→ messagesForApi = [baseline system] + projected history
```

### 分期

| Phase | 内容 | 优先级 |
|-------|------|--------|
| **1** | 真 `/compact`：LLM 摘要 + tool-pair 安全 cut；`prompt_too_long` 自动再试 | 最高 |
| **2** | ContextSource + epoch baseline；mode/git/instructions 中途刷新 | 高 |
| **3** | microcompact；薄 skills（列表 + 按需读）；摘要后 re-read 最近文件 | 中 |
| 不做（短期） | 全抄 Claude 五层、服务端 cache_edits、context collapse 双视图、子 agent | — |

### 取舍一句话

- 只增强 prune → 不够。  
- 只上 LLM `/compact` → **立刻改善体验**，工作量可控。  
- 完整 OpenCode epoch → 正确长期形态，适合 Phase 2。  
- 全抄五层 → 课程期内过重。

**推荐路径：Phase 1 → Phase 2；skills 用「列表 + 按需读文件」薄实现即可。**
